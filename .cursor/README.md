# Конфигурация агента в этом репозитории

Папка называется **`.cursor`**, не `.cursore`. Cursor читает её на любом ПК после `git clone` / `git pull`.

## Что куда класть

| Путь | Назначение | Когда срабатывает |
|------|------------|-------------------|
| `AGENTS.md` (корень) | Короткий вход для любого агента | Часто подхватывается сам |
| `.cursor/rules/*.mdc` | Постоянные правила проекта | `alwaysApply` или по `globs` |
| `.cursor/skills/*/SKILL.md` | Пошаговые сценарии | Когда описание скилла совпало с задачей |
| `readme/` | ТЗ и домен | Читать при продуктовых вопросах |

**Правило** — короткий контракт: архитектура, статус, «не делай X».  
**Скилл** — инструкция «как выполнить конкретную работу».  
**Роль** — как себя вести (учитель / бэкенд / фронт), не дублирует весь код.

## Формат `.mdc`

```markdown
---
description: Одна строка: зачем правило и когда его брать
globs: src/**/*.ts
alwaysApply: false
---

# Заголовок
Конкретные пункты. Лучше < 50–80 строк.
```

- `alwaysApply: true` — в каждый чат. Только то, без чего нельзя (статус, требования, роли).
- `globs` — правило подмешивается, когда открыты/меняются подходящие файлы.
- Одно правило = одна тема. Длинное ТЗ не копируй сюда целиком.

## Как этим пользоваться в чате

- «Объясни как новичку» → скилл `explain-for-beginner`
- «Добавь POST/PUT» → скилл `implement-crud-layer`
- «Локализация IT/BG» → скилл `add-xliff-i18n`
- Смена поведения: «работай как teacher / backend-implementer»

После смены правил новый чат видит их надёжнее, чем старый длинный тред.
